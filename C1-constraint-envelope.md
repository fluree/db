## 3. TIMEOUT-DESPITE-TUNING LIST (the materialization / async candidates)

For each: the binding constraint, the arithmetic, and the minimum change that flips it. All INFERRED from MEASURED anchors (56k rows/s/core; ~0.9-1.3s/table cold cross-region metadata RTT; 69,046-file whole-dataset; FACT 36-200M rows / 18-129 files).

1. **Big single-FACT grouped rollup (36-200M rows).** Binds: **CPU materialization** — `rows/(56k×6)` = 36M→107s, 60M→178s, 120M→357s, 200M→590s, all > the 180s cap (INFERRED; MEASURED anchor 56k/core). files_pruned=0 is CORRECT here (unfiltered GROUP BY — nothing to prune). Min change to flip: **aggregate/GROUP-BY pushdown** (T1.1, WEEKS) — compute the rollup columnar over the FK-key + measure columns without constructing an RDF term per row, then join the small grouped result to the dim; OR an **async envelope** (T1.5) that returns the answer past 180s. Not fixable by cache/region/compaction (moves zero rows) or more cores (Lambda maxed).
2. **2-FACT join rollup (OrderLine 120M ⋈ Order 36M).** Binds: **memory** — the HashJoin build buffers the ~36M-row interior fact + the join fan-out to ~8-10 GB (MEASURED the round-3 OOM forensics, 10,239 MB terminal). Post-wave-4 it fails **fast and typed** (RSS watchdog 85%/8704MB → 507, or engine budget 78% → 507/408, or 180s deadline) — a bounded failure, not a success. Min change to flip to SUCCESS: dim-scan **semi-join pushdown** (prune OrderLine to the filtered dim keys before the join — MEDIUM-LARGE, needs the parked `perf/r2rml-ref-value-set-pushdown` backend + a new dim-scan front-end) OR the full aggregate pushdown (T1.1). Live-feasible only for the filtered subset; the no-filter 2-FACT SUM is a rewrite, not a slice (READ the round-3 OOM forensics R1′: 5 orthogonal fusion blockers).
3. **Unfiltered VALUES scan (GlJournal ~50M, q040/q052/#9).** Binds: **missing lowering** — a `Pattern::Values` over a graph source is never emitted as an Iceberg IN-set scan filter → full unpruned scan + O(N×K) correlated match (READ w4-3 diagnosis; the ValuesOperator loop also had no cancel-poll, a wave-4 rider closed that). Min change: **VALUES→`col IN {values}` scan-filter lowering** — the pruning backend (`Expression::In`/`can_contain_file`, 86.6% measured on q041) is BUILT; the front-half (set-valued `ScanFilter` + rewrite emission) is the parked branch's work. DIAGNOSIS-ONLY / next-slate.
4. **Predicate-less whole-dataset COUNT (q056, 69,046 files).** Binds: **fetch floor** (345s cold at C=6) + un-fused COUNT decoding every object row. Min change: **fused predicate-less COUNT from Iceberg manifest `record_count`** (F22 / PR-6 sibling) — sub-second, zero data read; orthogonal to compaction (which only removes the 69k-request floor, not the row decode). READ(A.3 (c) note).
5. **get_data_model on a hybrid / non-empty-shell dataset.** Binds: **routing** — C2's manifest path is gated on `ledger.t()==0` empty-shell (READ handoff §1 C2); a virtual dataset that is also a committed ledger takes native `assemble_full_stats` → federated scan (READ A.6 "routing gap"). Now BOUNDED by the 180s/300s deadline (no longer a 900s runaway), but slow. Min change: extend manifest-stats routing to committed graph-source-federated ledgers (T1.2 engine, low-moderate).
6. **Cold-container first-ask at SF20 (any sweep-bound shape).** Binds: **fetch floor × cold catalog × half concurrency × no cross-container cache** — per-container `/tmp` is cold on every cold container; the shipped caching wins (loadTable pointer, disk-catalog, footer, parquet artifact) are ALL warm-container-only and evaporate cold (READ A §2d). Min change: **architecture** — shared/persistent cache (EFS/S3-backed catalog), region colocation (customer-region compute — the BYO bucket region is customer-owned), or source compaction. None live; all heavy or customer-controlled.
