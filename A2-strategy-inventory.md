## 0. Scope, counts, method

Method: (1) enumerated every `FLUREE_*` read in `fluree-db-query`/`fluree-db-iceberg`/`fluree-db-api` via `env_switch_enabled` call sites + raw `env::var`; (2) read the actual guard/decline branches at each site; (3) mapped each to its introducing commit on `a49ac3fc2..HEAD` and confirmed the wave/PR; (4) grepped the merge-base tree (`git grep FLUREE_ a49ac3fc2`) to separate baseline from branch; (5) cross-referenced `fluree-bench-virtual/corpus/manifest.json` (68 queries q001–q068) + PR bodies for corpus coverage.

Headline counts (`READ` + `git`): ~39 distinct `FLUREE_*` switches touch the virtual lineage — ~24 introduced on the branch, ~15 already at merge-base (#1450). ~44 distinct mechanisms total (some share a switch; ~9 are unswitched). The falsy convention for every boolean switch is the shared `env_switch_enabled` (`READ(fluree-db-query/src/r2rml/mod.rs:48)`): ON unless value ∈ {`0`,`false`,`off`,`no`} (trimmed, case-insensitive); unset/empty = ON; each read once into an `OnceLock` (set at process start, not per-query). The two iceberg booleans inline the same set (`READ(send_parquet.rs:54,180,197)`); `FLUREE_OPTIONAL_HASH_JOIN` uses inverted `disabled` logic but the same effect.
